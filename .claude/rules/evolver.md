# Evolver rules

- A comparison needs several seeds per setting, and says how many: 8 runs with the same settings ended between 96.3 and 139.3 against the 1,107 '94nop Koenigstuhl warriors (16th November 2026). On '94 one run per setting says nothing below about 15 points, 4 seeds per arm nothing below about 10 (the baseline of #196, seeds 301 to 304: 126.8 ± 7.1, `docs/evolver.md`). Start the arms from the same seeds or the same lists (`--start`).
- Score the same warriors at every look: the run's best.red and the 3 members best against the panel, each against the whole folder (`node tools/tournament.mjs warriors/koenigstuhl/94nop --rounds 100 --bench <file>`; `--islands` with `--select-after` does it itself). The holdout picks best.red and flatters it. An interim score of best.red alone said two arms had found nothing; their top three had (17th November 2026). `--select-after 100` with `--batches 1000` scores last at batch 900: score the end with `node tools/run-report.mjs <run> --bench --opponents <dir>`. With `--island-panels own` compare islands by the holdout or the bench, never by panel average: holdout minus panel was 13.5 to 42.4 per island in seed 304.
- Diversity is designs, not kinds of style: count the openings or the designs on top (`run-report`'s "Designs on top"). `tiny-p100-none16` had 4 kinds among its island leaders, and 14 of the 16 shared one `SPL #`/`DJN #` opening (26th November 2026).
- Several runs with one panel: `--islands`, or pick once and pass `--panel-files`. A pick (`--panel-choice kinds`) takes a minute on 32 threads and an hour on one, in every process.
- `--batches 0` and `--seconds 0` mean no limit, not none: `--batches 1` for a run that should only set itself up. On a resume `--batches N` is N more, and without it the run has no end: seed 302 of #196, stopped at batch 529, continues to 1000 with `--batches 471`.
- `--threads` changes the speed of a run, never its events. A run folder continues with `--threads`, `--batches`, `--seconds` and the few options its message names; an island folder with the first three only: other settings are a new run from its lists, `--start` with a folder `island-NN` per island of the members' `gen` (`docs/evolver.md`, `dc16-p100`).
- A new option goes into: the `params` struct, `event_start`, the state (at the end of `param_fields` in `state.c`, which is the `params` line, with its default for older states; a removed option keeps its place there as `GONE()`, so a state that used it is refused by name, #193), `params_error()`, the usage text, the table of `docs/evolver.md`, and `checkValues` of the test when it changes a value.
- Since #187 a new run writes `--events brief`: a newcomer that leaves in its batch is an enter line with `"brief":true` and no `scores`, `screenPoints`, `code` or `gen`, and without its complete line. A new reader of `events.jsonl` (dashboard, tools) handles such lines; a test that replays matches or push-offs runs with `--events full` (TINY has it), and `test/evolver-brief.test.js` checks that the two give the same run.
- Reading `events.jsonl`: a result is `[opponent, wins, losses, ties, seed]`; a member's panel average is the 6th field of its row in `values`, while the log line's "best value (X, avg N)" is the push-off average over everyone (a panel average of 68.5 was reported as 143.8, 27th November 2026). The last line of a running run can be half written: skip a line that does not parse. A `rotate` event is a new panel warrior: a foe of `--groups` (`from` its island and id) or a hill warrior of `--ladder` (`from` `[0, 0]`); from then on the panel is not `start.panel` (`checkValues` and `checkLadder` of `test/evolver-common.js` follow it).
- Mutants of `evolver/*.c`: `node .claude/skills/engine-check/mutate.mjs <mutants.json> --timeout 600 -- <test command>`, the test command `node --test --test-name-pattern='<re>' test/evolver*.test.js` (or the one file of the test). The test builds `42evolve` from the tree (test/native.js, cached in `build/test/`); check that a mutant failed on an assertion, not on the build.
- Long runs: `chrt -i 0 nice -n 19 build/42evolve ...` (the idle class: other work gets the CPU first, the run all of it when the machine is idle; a user cannot raise it again), two runs in it share the cores evenly (SCHED_IDLE has no `nice`: a second run halves the first, and only root gives one back the normal class with `chrt -o -a -p 0 <pid>`); started by a script that logs into a file and goes on by itself (score, next leg), as a systemd user service with its binary, opponents and script in a folder of its own under `~/` (`systemd-run --user --unit=<name> sh <script>`): a `nohup` or `setsid` child stays in the session's cgroup and dies when the session restarts, and the scratchpad is in `/tmp` (#196: a chain started 5 hours late). `42evolve` ends on SIGTERM only after the current batch, not during the pick: `timeout` does not stop a test start, `kill -KILL` its PID. The run folders are `~/42evolve.<name>`; `node tools/serve.mjs --run ~/42evolve.<name> ...` shows them.
